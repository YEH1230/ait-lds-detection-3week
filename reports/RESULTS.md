# AIT-LDS v1.0 평가 결과

평가 기준일: 2026-08-21  
기본 라벨 정책: 두 번째 열 `event`(유사도·순서 기반)  
평가 단위: 로그 한 줄/이벤트. 공격 체인 단위 지표가 아님.

## 데이터 분리

| 역할 | 테스트베드 | 사용 방식 |
|---|---|---|
| 개발 | `mail.cup.com` | 정규화기와 최초 규칙 작성 |
| 규칙 개선 | `mail.insect.com` | 최초 Nikto 규칙의 과적합 발견 및 일반화 |
| 최종 미사용 검증 | `mail.onion.com` | 규칙을 더 수정하지 않고 최종 평가 |

최초 Nikto 규칙은 `HTTP 400 + 빈 User-Agent`에만 의존해 `mail.insect.com`의 Nikto 6,296건 중 81건만 탐지했다. 이를 `User-Agent`의 명시적 `Nikto/` 식별자 또는 기존의 비정상 조합으로 일반화했다. 따라서 `mail.insect.com`은 최종 holdout이 아니라 개선 데이터로 명확히 구분한다.

| 규칙 | TP | FP | FN | 해석 |

| Nikto scanner | 6,295 | 0 | 0 | 정찰 행위 전부 탐지 |

유일한 FN은 공격 시간대에 끼어 라벨이 `hydra`가 된 `::1 OPTIONS *` Apache 내부 더미 연결이다. 공격자 요청이나 Hydra 행위가 아니므로 규칙에 추가하면 오히려 논리적 오탐이 된다. 이는 라벨 노이즈로 기록하고 규칙을 왜곡하지 않았다.

오탐 22건은 모두 정상 사용자의 실제 Dovecot 인증 실패다. 단일 인증 실패 이벤트만으로는 Hydra와 정상 입력 실수를 의미 있게 분리할 수 없다. 이 규칙의 심각도를 `low`로 두고 Detection Seed만 만들게 한 이유다. 다음 단계에서는 같은 사용자/출발지의 실패 횟수를 시간 창으로 묶는 Sigma correlation(`event_count`)과 Apache Hydra Seed의 시간·계정 상관관계를 적용해야 한다.

## 판정

- 정규화: 세 테스트베드의 Apache와 auth 샘플에서 파싱 실패 0건.
- 웹 공격 Seed: 최종 미사용 검증에서 정상 오탐 0건, 실제 공격 행위는 전부 탐지. 라벨 노이즈 1건만 FN.
- 인증 실패 Seed: 공격 재현율은 100%이나 정상 실패도 포함하므로 단독 고심각도 경보로 사용할 수 없음.
- 배포 전 필수 보완: 인증 실패 시간 창 집계, auditd/Suricata 교차 증거, 더 많은 테스트베드와 실제 운영 정상 로그 검증, Sigma 전체 호환이 필요하면 pySigma 계열 백엔드 채택.
